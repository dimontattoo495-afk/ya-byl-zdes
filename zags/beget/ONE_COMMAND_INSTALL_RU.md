# Установка приватной схемы ЗАГСа на Beget — ОДНА КОМАНДА

Это **не полноценный запуск**. Сценарий создаёт только новые пустые таблицы `zags.couples` и `zags.wishes` в существующем локальном PostgreSQL, а также RPC `public.zags_v2_action`, **доступный только роли `service_role`**. Для браузерных пользователей и публичного PostgREST API он остаётся недоступным до отдельного релиза. Публичный сайт ЗАГСа, существующие платежи, TATTOO PRICE, Docker/Caddy и зарубежный Supabase не изменяются.

## Перед установкой (результаты проверки 21 октября 2026 года)

- VPS Ubuntu 24.04, Beget Санкт-Петербург, `supabase-db` запущен.
- `auth.users` существует; `zags` отсутствует; таблиц `tp_*` — 14.
- Сделаны и сохранены на ПК три независимых архива: PostgreSQL custom dump, Storage + сайт + functions/Caddy, конфигурация Supabase.
- Архивы **ещё не проверены сравнением SHA256 между VPS и ПК**, а состояние автоматических бэкапов Beget не подтверждено. Защиту ПК и файлов обеспечивает владелец.
- Браузерные тесты и миграция на синтетическом PostgreSQL 17 успешно проходят GitHub Actions.
- Прямого SSH-доступа к VPS у ChatGPT нет: владелец запускает установку в подключённом SSH сеансе и присылает текст результата без паролей/ключей.

## Однокомандная установка из неизменяемого коммита

Использовать только SHA коммита, который прошёл зелёные тесты, и вставлять команду в терминал VPS с приглашением `root@...#`. Команду публикуем в диалоге после прохождения тестов. Она скачивает **только** `install-private-zags.sh` с точного Git commit SHA и запускает его, передавая тот же SHA для загрузки `001` и `002`.

Сценарий сам:
1. Проверит наличие на VPS всех трёх архивов и их читаемость, свободное место и готовность PostgreSQL.
2. Убедится, что схема `zags` и RPC отсутствуют, `auth.users` существует, нужные роли есть и TATTOO PRICE по-прежнему имеет 14 таблиц.
3. Скачает обе версии SQL из **того же фиксированного коммита GitHub**.
4. Применит их **единой транзакцией**; ошибка PostgreSQL откатывает обе миграции.
5. Проконтролирует отсутствие публичного доступа и пустые таблицы, сверит число таблиц `tp_*`.
6. Выведет `PASS` при успешной установке.

Сценарий **не переносит** пользователей и данные из облачного Supabase и не открывает реальные платежи. Не повторять команду, если установка прошла: повторный запуск должен безопасно остановиться на существующей схеме.

## Следующие этапы, отдельно

- Настройка API endpoint на Beget, его HTTPS/CORS и локальной авторизации в отдельной тестовой среде.
- Юридически проверенный порядок сбора/локализации ПДн пользователей РФ, отдельная оферта и механизм их удаления.
- Контролируемая миграция существующей одной неоплаченной заявки, с повторным подтверждением аккаунтов без копирования паролей, токенов и OTP.
- Только после испытаний — отдельный выпуск и подключение платёжного обработчика ЗАГСа; по умолчанию платёжный флаг выключен.

**Не запускать** `docker prune`, не удалять старый снапшот, не выполнять восстановление поверх рабочей БД, не пересылать `.env` и архивы в чат.
